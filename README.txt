ПАКЕТНЫЙ КОНВЕРТЕР DOCX → HTML

Требования: Python 3.10 или новее. Microsoft Word и сторонние библиотеки не нужны.

БЫСТРЫЙ ЗАПУСК
Дважды нажмите run.bat. Программа обработает все DOCX в папке:
  %USERPROFILE%\Downloads\Telegram Desktop\Лекции (1)\Лекции
Результаты появятся в папке output рядом с программой.
run.bat также создаёт папку pdf-parts с частями по 5 страниц для PDF-экспорта.
Вложенные папки сохраняются. Временные файлы Word (~$...) исключаются.
Исходные документы программа не изменяет.

ЗАПУСК ИЗ ТЕРМИНАЛА
  python convert.py
  python convert.py "D:\Лекции" -o "D:\HTML"
  python convert.py "D:\Лекции\Лекция 1.docx" -o output

По умолчанию создаются HTML для импорта и редактирования в сервисе: без head
и встроенного CSS. Изображения остаются внутри файла. Выравнивание задаётся
классами редактора text-align-*, justify-content-* и align-items-* для lg/tb/mb.
Собственные стили просмотра не попадают в сервис и не мешают его настройкам.

Для импорта в редактор, ожидающий именно HTML-фрагмент как в образце:
  python convert.py --fragment -o output-fragments
Параметр --fragment сохранён для совместимости; теперь это режим по умолчанию.
Файл начинается со страницы <div data-element-type="page">. Для отображения
фрагмента нужны стили принимающего редактора.

Для просмотра в браузере создайте отдельную копию со стилями:
  python convert.py --standalone -o preview --overwrite
Файлы preview предназначены для просмотра, в сервис загружайте файлы output.
Встроенные стили просмотра поддерживают классы выравнивания для lg/tb/mb.

Повторный запуск пропускает существующие HTML. Для обновления результатов:
  python convert.py --overwrite

Другие параметры:
  --template "образец.html"   использовать другой образец form5/form5a
  --no-frame                 убрать рамку ГОСТ, сохранив атрибуты редактора
  --page-chars 4200           приблизительный объём страницы без границ Word
  --help                     все параметры

ЭКСПОРТ PDF В СЕРВИСЕ
Если сервис рисует весь документ в один canvas, длинная лекция может дать
пустой PDF из-за ограничения размера canvas. Одной правкой HTML механизм
экспорта сервиса изменить нельзя. Без исходников сервиса используйте части.

Разбить уже готовые HTML:
  python split_html.py output -o pdf-parts --pages 5
Разбить один HTML (включая файл, скачанный из сервиса):
  python split_html.py "D:\Лекция.html" -o pdf-parts --pages 5
Одновременно с конвертацией DOCX:
  python convert.py --pdf-parts pdf-parts --part-pages 5

Откройте папку нужной лекции в pdf-parts. Загружайте каждый part-XXX отдельно
в отдельный документ сервиса и экспортируйте его PDF. Не собирайте части
в один документ редактора: это снова создаст большой canvas. Экспортированные
PDF можно затем объединить по номерам частей в PDF-редакторе.

Страницы, исходная нумерация, текст, таблицы, формулы и картинки сохраняются.
Оглавление остаётся на исходной странице. Ссылки внутри части сохраняются,
а ссылки на другие части становятся обычным текстом с номером страницы.
manifest.json перечисляет части, диапазоны страниц и контрольные суммы.

5 страниц — консервативный размер для описанного десктопного экспорта 800px
при scale=2 (оценочно 1600 x 11314 px вместо 1600 x 70145 px для 31 страницы).
Фактический размер зависит от CSS сервиса и высоты страниц. Это не гарантия
для любого устройства. Если отдельная часть всё ещё выходит пустой, используйте
--pages 1. Проверка кнопкой экспорта сервиса не выполнялась.
Документация: https://html2canvas.github.io/html2canvas/faq/

СТРУКТУРА
  convert.py          конвертер и командная строка
  layout.py           оформление лекций по новому HTML-образцу
  split_html.py       разбиение готового HTML на части для PDF-экспорта
  page-template.html  рамки form5/form5a, извлечённые из предоставленного образца
  style.css           базовое оформление автономного HTML
  run.bat             запуск в Windows
  verify.py           проверка сохранности текста, изображений, таблиц и ID
  reference_checks.py проверка пустых страниц, оглавления и соответствия эталону
  reference-lecture-1.json  контрольный снимок присланного эталона лекции 1
  output/report.json  результат каждого файла и предупреждения

Сохраняются рамки ГОСТ, data-element-type, data-element-container, уникальные
element-N, адаптивные классы lg/tb/mb, текстовые spans, таблицы div, изображения.
Текст образца в лекции не подставляется. Редактируемые поля авторов/кодов очищены,
название берётся из имени файла, номера страниц формируются автоматически.

ВОЗМОЖНОСТИ И ОГРАНИЧЕНИЯ
Переносятся абзацы, заголовки, полужирный/курсив/подчёркивание, выравнивание,
ссылки http/https/mailto, встроенные изображения, таблицы с объединением ячеек.
Списки отображаются текстовыми маркерами; сложные схемы нумерации упрощаются.
Базовые формулы OMML преобразуются в MathML (дроби, индексы, корни, скобки).
Оформление унифицировано по образцу лекции: текст 18px, таблицы 13px,
подписи 16px, межстрочный интервал 140%. Контейнер имеет классы p-*-l/r-7.
В автономном CSS боковой отступ составляет 28px, красная строка — 1.25cm.
Эти физические значения подобраны, поскольку образец не содержит CSS.
Изображения — отдельные центрированные div с adaptive-width. Ширина lg
рассчитывается как ширина изображения в DOCX / 660px, максимум 100%; на
узких экранах — 100%. Подпись из следующего абзаца «Рисунок N…» включается
в image-label и alt. Бинарные данные изображений остаются исходными.
Оглавление собирается целиком, включая продолжения на следующих страницах.
Названия сопоставляются с заголовками; при изменённом названии используется
уникальный номер раздела. Недостающие пункты добавляются по заголовкам.
Если оглавления в исходнике нет, оно создаётся из заголовков.
Пункты старого оглавления, для которых разделов в DOCX уже нет, исключаются
с предупреждением в report.json. В лекции 3 таких устаревших пунктов пять.
Номера страниц и ссылки рассчитываются после удаления пустых страниц.
Заголовки h1/h2 преобразуются в h3/h5 образца.
Разметка блоков записывается с отступами для чтения исходного HTML.

DOCX не содержит готовой браузерной вёрстки. Страницы НЕ совпадают с Word
пиксель в пиксель: сохранённые разрывы внутри абзацев переносятся с разбиением
абзаца на продолжения; если границ нет, страницы разбиваются приблизительно.
Страницы без содержимого, возникающие из повторных разрывов, удаляются;
титульные отступы, страницы с изображениями и таблицами сохраняются.
Таблицы целиком остаются на странице; разрыв в таблице переносится перед ней;
большая таблица/абзац может увеличить её высоту. При печати браузер может
дополнительно разбить такую страницу. Фиксированного обрезания содержимого нет.
Разрывы разделов, плавающие объекты и многоколоночная вёрстка не воспроизводятся.
Колонтитулы Word заменены рамкой HTML; их текст и картинки не переносятся.
OLE, VML, сноски и сложные математические конструкции требуют ручной проверки.
Внешние изображения не загружаются. Неподдерживаемые браузером форматы картинок
сохраняются как data URI, но могут не отображаться.
Структура рамки взята из образца; CSS для самостоятельного просмотра написан
заново, поскольку исходный HTML не содержит CSS. Полное визуальное совпадение
и совместимость импорта с конкретным редактором без его спецификации не проверены.

ПРОВЕРКА
  python -m unittest -q test_convert.py test_split_html.py
  python verify.py
Проверяет результаты в output для стандартной папки лекций. Можно указать пути:
  python verify.py "D:\Лекции" "D:\HTML"
Перед сохранением каждого HTML конвертер автоматически проверяет отсутствие
пустых страниц, уникальность ID, полноту оглавления, его ссылки и номера страниц.
verify.py дополнительно проверяет текст основного документа и двоичные данные
изображений относительно DOCX, количество таблиц и формул. Числа в оглавлении
проверяются по реальным страницам HTML, поскольку в исходнике они устаревают.
При наличии лекции 1 результат сравнивается с сохранённым снимком эталона:
текст и структура всех 31 страниц, изображения, подписи, адаптивные размеры
и пункты оглавления. В эталоне два старых номера: раздел 2.2 указан на стр. 10,
хотя заголовок на стр. 9; раздел 3.4 указан на стр. 17, хотя он на стр. 16.
Проверка учитывает эти две исправленные ссылки; сам эталон не изменяется.
Код завершения convert.py: 0 — успех/пропуск, 1 — ошибки отдельных файлов,
2 — неверные аргументы. Ошибка одного DOCX не останавливает остальные.
report.json относится к последнему запуску (в том числе пропускам).
